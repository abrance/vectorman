# 需求实施计划

本 feature 是 `apm-tracing` 与 `ebpf-observability` 聚合指标可清理的前置依赖，应先于两份观测 spec 的聚合落地。本期只交付设计，本清单为待实施拆分。

- [x] 1. 类型与 trait 扩展
  - [x] 1.1 `TsRetentionConfig`、`TsMatcher`/`TsMatcherOp`、`TsSeriesSelection`、`TsDeleteReport`、`TsStorageStats`
    - 状态：已实现（PR #29）
    - 对应需求 1.1、2.1-2.3、5.1-5.2 与设计类型定义
  - [x] 1.2 `TimeSeriesStore` 新增 `delete_series`（默认返回 `query_failed`）与 `storage_stats`（默认零值）
    - 状态：已实现（PR #29）
    - 对应需求 6.3
  - [x] 1.3 桩测试：只实现既有三方法的存储，断言默认实现行为
    - 状态：已实现（PR #29）
- [x] 2. tsink 适配
  - [x] 2.1 `TsinkTimeSeriesStore::new(data_path, TsRetentionConfig)`，按「先 `with_retention`、后 `with_retention_enforced`」顺序配置
    - 状态：已实现（PR #29）
    - 对应需求 1.1-1.3 与设计 Pitfalls 第二条
  - [x] 2.2 上限透传：`with_cardinality_limit` / `with_memory_limit` / `with_wal_size_limit`（0 表示不传）
    - 状态：已实现（PR #29）
    - 对应需求 4.1-4.2
  - [x] 2.3 `delete_series` 适配：`TsSeriesSelection` → `tsink::SeriesSelection`（必填双端时间范围）→ `DeleteSeriesResult` 投影
    - 状态：已实现（PR #29）
    - 对应需求 2.4、2.8-2.9
  - [x] 2.4 错误映射：`InvalidTimeRange` → `invalid_argument`；`delete_series is not implemented` 与墓碑落盘失败 → `query_failed`；超窗写入 → `invalid_argument`；基数拒绝 → `query_failed` 含 `cardinality`
    - 状态：已实现（PR #29）
    - 对应需求 1.5、2.5-2.7、4.3
  - [x] 2.5 `storage_stats` 适配：`observability_snapshot()` 字段投影 + 本地配置回显 + `list_metrics()` 按需采样
    - 状态：已实现（PR #29）
    - 对应需求 5.2 与设计来源映射表
  - [x] 2.6 单测：超窗点被拒/被拒消息、`enforced=false` 兼容、删除生效与范围外不受影响、重复删除幂等、非法范围、基数上限达峰后的行为、统计字段一致性
    - 状态：已实现（PR #29）：8 个单测全绿
